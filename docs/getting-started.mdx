Plan with [Coordinator Chat](/coordinator), let workers handle tasks, and review their
results beside the conversation. This guide takes an existing project from its first
conversation to a completed task.

![Flowfield board with tasks, priorities and work ready for review](/images/board-overview.png)

## Install and start

Install and sign in to [Codex CLI](https://developers.openai.com/codex/cli/). Then install Flowfield with [uv](https://docs.astral.sh/uv/getting-started/installation/):

```sh
uv tool install --python 3.12 flowfield-core
flowfield harness install codex
flowfield serve
```

Your browser opens at [localhost:8765](http://127.0.0.1:8765). Keep the terminal open;
Ctrl-C stops the service. Use `--no-open` to keep the browser closed.
See [Installation](/installation#alternative-pip) for the pip alternative. Managed workers also need Git.

## Add your project

Choose **Add project** in the sidebar, then **Choose directory**. The native folder chooser
opens on the machine running Flowfield. Select your existing project directory and click
**Add project**. Its name and task prefix are derived automatically; project settings let
you adjust them. Use **Project details (optional)** to choose a name, unique ID or three-letter
task prefix if the derived values conflict with another project.

You can also register the same project from another terminal in its directory:

```sh
flowfield project init
```

Registration adds `.flowfield/config.toml`. Flowfield adopts your project; it does not
create directories, initialize Git or scaffold an application. Without a desktop folder
chooser, use the CLI option.

## Start planning

Choose your model, reasoning effort and access mode beside the input in [Coordinator Chat](/coordinator)
and save. Describe what you want to achieve. For example:

> Help me add CSV export to this project. Review the existing code and suggest a small first task before starting implementation.

Chat is scoped to the selected project.
Flowfield automatically uses the local machine; worker checks and delivery configuration
can wait until you are ready to run tasks.

Built-in chat supplies its own MCP connection. To plan from a standalone Codex session,
follow [standalone coordinator setup](/integrations/codex#connect-a-standalone-coordinator)
instead.

## Prepare the first task

When you’re ready to run tasks, preview and install project guidance in **Coordinator**
settings or through the CLI:

```sh
flowfield project guidance preview
flowfield project guidance install
```

Installation preserves existing instructions and adds a reference to
`.agents/skills/flowfield-coordinator/SKILL.md`. Review and commit the added files under
your project's usual rules before running workers.

Ask your coordinator to help choose worker settings for the project: choose the target
branch, dependency setup, checks and a local run command, then validate the environment.
Choose a worker model and reasoning effort explicitly. These settings are also available
under the settings icon beside the project name.

Project **Workers** settings supply defaults for model, effort and access. Individual
tasks can override them; changes apply to the next attempt. See [Concepts](/concepts#agent-settings-and-permissions) for the worker environment.

Describe one small change and its success criteria. Ask the coordinator to capture and
prepare the task in Flowfield. Open its feed to read the agreed definition. The coordinator
maintains task intent; you control priorities and review.

## Run the task

Move the task to **Up next** and click **Run queue**. Ready tasks run when their
dependencies, setup and input requirements are satisfied. The task moves to **In progress**;
its feed shows worker activity and any questions.

Answer questions in the task feed or **Needs you**. Your saved answer lets the service
continue managed work when the queue permits it. **Pause queue** prevents new starts;
active workers continue. **Stop worker** stops the selected attempt.

## Review and finish

When the task reaches **In review**, read its result and checks. Inspect the diff or use
**Try result** to test an independent copy of that exact version. Record testing in the
feed, request changes, or choose **Approve and integrate** for the selected result.

![A task feed beside Coordinator Chat, with a result ready for review](/images/overview.png)

Open **Code changes** to inspect the exact candidate before approving it.

![Code review beside the coordinator conversation](/images/code-review.png)

Flowfield delivers approved code to your configured project checkout, then marks the task
**Done**. Local edits that prevent delivery remain intact and the result explains the next
action. A complete report-only task can finish without code approval.

To run independent tasks together, set **Maximum parallel workers** to **2** under
**Workers**. Dependent tasks wait until prerequisite work is complete and its code is available.
