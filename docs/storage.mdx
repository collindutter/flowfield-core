---
title: Local storage
description: Where your workspace lives and how to preserve it.
---

Flowfield stores its workspace separately from the installed application and your source code.

| Location | Contents |
| --- | --- |
| `~/.flowfield/` | Workspace database, execution artifacts and service-owned workspaces |
| `project/.flowfield/config.toml` | Portable project identity |
| `project/.flowfield/guidance.json` | Ownership of installed guidance |
| `project/.agents/skills/flowfield-coordinator/SKILL.md` | Coordinator instructions |

Choose another workspace directory with `FLOWFIELD_DATA_DIR` or `flowfield --data-dir
/absolute/path serve`. Project checkouts and their local edits remain separate from task state.

Stop the service before backing up the workspace directory, and preserve the whole
directory together with the relevant project repositories. Keep a backup before upgrading.

An incompatible database is preserved and rejected rather than reset. Use its matching
build to reopen it. Reinstalling an older application does not downgrade a newer database.

The browser updates task state through the service. CLI commands and agent tools use that
same service rather than independently opening the database. The queue is paused after restart.
