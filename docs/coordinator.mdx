---
title: Coordinator Chat
description: Plan work and capture tasks beside the board.
---

Coordinator Chat is the conversation beside your project's board. Discuss an outcome,
ask it to capture and prepare tasks, or reconcile saved project answers. Task links open
the same feeds you use for questions and review.

## Start planning

Install and authenticate [Codex](/integrations/codex), including the managed ACP runtime.
Add an existing project using **Add project → Choose directory** or `flowfield project init`.
In Coordinator Chat, choose a model, reasoning effort and native access mode beside the input, then save.
Local uses the service host’s tools, credentials and native harness configuration automatically.
Worker delivery branches, setup and checks can be configured later. Built-in chat supplies
its own MCP connection; `flowfield integration connect codex` is only for standalone sessions.

Write your message and select **Send** (or press Enter). Use Command/Ctrl+Enter or
Shift+Enter for a new line. Opening a project
starts no model turn. Send is available once you have saved these choices.
The coordinator manages work through project-scoped Flowfield tools. You can also ask it
to configure the project or local environment directly, within its selected access mode.
These setup changes affect the project directory immediately; they do not produce a task
result for approval. Agreed implementation work belongs to task workers. Answer worker
questions and approve exact code results in their task feeds.

Use the model button beside the input to change model, effort or access. Changes apply to the next
message; a running turn keeps its saved choice. Standalone coding-agent settings are separate.

Access modes come from Codex, including Read only, workspace access and Auto review.
Existing chats retain read-only access until you change it. Auto review uses Codex's native
reviewer; permission requests that need your answer appear in the chat and **Needs you**.
Answer one of the offered options while the turn is waiting. Stopping or ending the turn
closes its requests. Tool permission does not approve a worker's code result.
Default/Plan collaboration modes are separate and are not exposed here.

## Composer controls

The input grows as you write. Use the paperclip, drop files onto the input, or paste an image
to attach it. Remove an attachment with its × button before sending. Sent files are saved
with the conversation and can be downloaded from their message links.

You can attach up to four files: UTF-8 text/code up to 64 KiB each, or PNG, JPEG and WebP
images up to 2 MiB each. Their contents accompany the message sent to the agent; images
require image support from the connected harness. Coordinator attachments remain part of
its native session history, subject to Codex's context management. Reattach a file if you
start a new session or need details that compaction has omitted. Previously sent files
remain available to download. Worker replies use separate task attempts; reattach files
when a later reply needs their contents.
Each project has 128 MiB of attachment storage. Unsent uploads expire after 24 hours.

Type `/` for commands, separated into **Flowfield** and **Codex** groups. Flowfield actions
control the composer: `/attach` adds files, `/model` opens settings, and `/stop` stops a turn.
Use arrow keys and Enter to choose, or Escape to continue writing.

Codex commands are discovered from the installed harness without starting a model turn.
Select a command to insert `/codex <command>`, then send it. The prefix distinguishes
harness commands from Flowfield actions. **Reload Codex commands** refreshes the menu;
execution always checks what the current session supports.

| Command | Effect |
| --- | --- |
| `/codex compact` | Ask Codex to compact the ongoing native conversation. |
| `/codex status` | Show available native session information. Usage may be unavailable immediately after resuming. |
| `/codex mcp` | List the session's MCP connections. |
| `/codex skills` | List skills discovered by Codex. |
| `/codex rename <name>` | Rename the native Codex session; the Flowfield project name stays the same. |

Compaction and renaming require an existing conversation. Native commands do not accept
attachments. Other discovered commands stay disabled with a reason: Plan, autonomous goals,
review commands and skill invocation need additional integration; signing out affects the
host account. Worker replies currently offer only Flowfield composer actions.

Hover or focus the context ring for the agent's reported context usage. During a turn it
shows that turn's latest report; afterward it shows the last turn. It stays empty until
the agent reports usage. Context occupancy is separate from billable token usage.

## Follow and stop

Replies and public tool activity stream in order, with tool activity shown in grey;
private reasoning is never displayed. A grey session note explains whether history was
resumed, and the status below each reply stays visible even before output arrives.
One coordinator turn can run per project, independently
of worker slots. You can write your next draft while it runs, then send when it finishes.

**Stop** ends the selected coordinator turn. Saved task changes remain, and task workers
continue independently. If a connection fails, the retained turn explains whether it stopped
or needs recovery. Flowfield never replays an interrupted prompt. If native cleanup could not
be confirmed, stop the remaining coordinator process on the host before choosing
**Confirm coordinator stopped**.

## Continue later

Each project has one ongoing coordinator conversation. Messages, public output and turn settings
are saved by the service. Older messages load on demand and stay visible as new replies arrive.
Long output is bounded and omissions are marked. Tool activity shows names, status and
available commands or paths.

Messages resume the same native Codex session, including its tool history and native
context management, across turns and service restarts. Each turn gets a fresh scoped
Flowfield connection. Stopping a turn ends its processes without deleting the saved session.

Chats created before native continuity use a one-time handoff of up to eight recent saved
exchanges within a bounded context budget. Omissions are marked; old native tool history
cannot be reconstructed. Later messages resume the new session normally.

If Codex cannot resume a session, Flowfield keeps the chat and reports the failure. Check
Codex on the service host and send a new message to retry, or choose **Start new session**.
That choice requires confirmation and uses the same bounded handoff; it does not restore
native tool history or earlier attachment contents. No failed prompt is replayed automatically.
Record important ongoing intent in tasks and decisions.

Resize the chat and work panes on a wide screen. On narrow screens, switch between
**Coordinator** and **Work**; switching preserves the current draft.
