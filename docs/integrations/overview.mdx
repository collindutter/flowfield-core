Flowfield connects your coding conversation to its workspace through two complementary tools.

**The project skill** explains how a coordinator captures agreed work, reads the board,
prepares tasks, answers project-level questions and helps you review results. Installation
adds `.agents/skills/flowfield-coordinator/SKILL.md` and a short reference in your project's
`AGENTS.md`, preserving existing instructions.

**MCP** exposes project and task operations through the local service at
`http://127.0.0.1:8765/mcp/`. Tools share the browser and CLI's revision checks, input
bindings and exact-result approval rules. Agents receive bounded briefings and can retrieve
specific definitions, feed entries, previous results and source evidence when needed.
The server publishes each tool's name, description and parameter schema through MCP
discovery; your agent reads these directly.

Managed workers receive scoped assignments and access to the tools their work needs.
Worker instructions are distinct from coordinator guidance. Harness-specific transport,
model capabilities and execution events live in adapters; tasks and review keep the same
meaning across interfaces.

## Harnesses

[Codex](/integrations/codex) is the first implemented integration, covering coordinator
MCP setup and service-managed workers. Additional harness integrations are planned.
Model choice stays explicit and capability support is determined by each adapter.

Installing Flowfield does not install or authenticate a harness. After changing an MCP
connection or project skill, start a fresh coding conversation to load the new configuration.
