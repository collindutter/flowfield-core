Workspace commands talk to your running local service. Commands inside a registered
project discover its identity from `.flowfield/config.toml`. Use `--project ID` when
working elsewhere, and `--help` at any command level for its options.

## Service and version

```sh
flowfield serve
flowfield --version
flowfield version --json
flowfield --help
```

Global `--port` selects the service. `--data-dir` or `FLOWFIELD_DATA_DIR` selects storage;
`FLOWFIELD_PORT` sets the default port for the service and CLI. A command-line port
overrides it. For example:

```sh
flowfield --port 8770 serve
flowfield --port 8770 project list
```

## Updates

```sh
flowfield update status
flowfield update check
flowfield update status --json
```

`status` reads the service's shared result, or the saved cache when the service is stopped.
`check` requests a manual check from the running service and waits briefly for the result.
Both accept `--json`; human update notices and errors use stderr. An unsuccessful manual
check exits with an error. These commands do not install software or start a service.
See [installation](/installation#update) for upgrade instructions and automatic checks.

## Storage and recovery

```sh
flowfield storage status
flowfield storage backups
flowfield storage restore BACKUP_ID --confirm
```

Storage commands run offline and accept `--json`. Status and backup listing do not
initialize or migrate the workspace. Recovery requires a stopped service and refuses
to discard writes made since the snapshot. See [local storage](/storage) for automatic
migrations, recovery limits and full backups.

## Projects and guidance

```sh
flowfield project init
flowfield project list
flowfield project show
flowfield project guidance preview
flowfield project guidance install
flowfield project guidance show
```

`project init /absolute/path` adopts an existing directory. Initial `--id`, `--name`
and `--prefix` override derived values. The three-letter task prefix locks after the first task.
The browser's **Add project → Choose directory** uses the same registration operation.
`project guidance export --part coordinator` prints the packaged skill without connecting
to a service. `project guidance remove` removes unchanged owned content and preserves local edits.

## Tasks and milestones

```sh
flowfield task list
flowfield task show APP-1
flowfield task activity APP-1
flowfield task relationships APP-1
flowfield task revisions APP-1
flowfield milestone list
flowfield milestone --help
```

Use stable task keys or IDs. The coordinator prepares task definitions through MCP;
CLI task operations expose the same workspace rules. Task dependencies and readiness
are checked by the service.

## Questions, execution and results

```sh
flowfield inbox list
flowfield inbox show QUESTION_ID
flowfield project workers show
flowfield project workers models
flowfield project workers run
flowfield project workers pause
flowfield task runs list
flowfield task runs show ATTEMPT_ID
flowfield task results list APP-1
flowfield task results show RESULT_ID
```

`project workers run` enables eligible Up next starts; `pause` leaves active workers
running. `task runs stop ATTEMPT_ID` targets one attempt. Inspect `task results review
--help` for exact-candidate approval and request-changes options; a result revision and
candidate commit are required. `task results retry-delivery --help` describes recovery
when approved code is blocked from reaching the checkout.

Use `project workers models` to read model IDs and supported reasoning efforts, then
`project workers configure --help` for explicit model, effort and parallel-worker settings.
Saving worker settings does not enable the queue.

Questions and replies preserve their task, attempt and result bindings. Answering does
not enable a paused queue; inspecting a result does not approve it.

## Project integration

```sh
flowfield project integration show
flowfield project integration configure --target main --check "make test"
```

Configure the target branch and trusted project checks to match your repository.
Repeat `--check` for multiple commands; `--setup` adds dependency setup. Your coordinator
can configure and validate richer environment and run-command settings through MCP.
Flowfield automatically uses the service host’s tools, credentials and native harness
configuration. Workers also need a native mode: use `worker models --json` to see choices, then pass `--mode MODE_ID` to
`worker configure` together with the model and effort.

## Harness connections

```sh
flowfield integration connect codex
flowfield integration status codex
flowfield integration disconnect codex
```

See [Codex](/integrations/codex) for project setup and fresh-session verification.

## Managed runtime installation

```sh
flowfield harness install codex
flowfield harness status codex
```

Install downloads the standalone ACP executable matching your Flowfield release and
platform, verifies its checksum, and saves it in the selected data directory. It uses
your existing Codex installation. Node and Bun are not required to run the bridge.
Status checks installed files and the Codex path without starting an agent.

For a locally built or downloaded bundle:

```sh
flowfield harness install codex --bundle /path/to/bundle.zip --sha256 CHECKSUM
```

Both commands work with the service stopped and accept `--json`. Installation preserves
previous executable paths and does not enable queues or change project access settings.

## Automation

Add `--json` to data commands for structured output. Errors go to stderr with a nonzero
exit status. Versioned edits require the current revision; do not overwrite newer intent
from an outdated read. Paged reads return cursors and truncation metadata: follow them
rather than treating the first page as complete history.
